# Deployment Guide — ClientFlow AI

Deploy the **frontend** to Vercel and the **backend** to Render. Supabase stays your database.

## Architecture

```
Vercel (React)  →  Render (Spring Boot)  →  Supabase (PostgreSQL)
                         ↓
                    OpenAI API
```

---

## Before you start

You need:

- GitHub repo connected: `rooomaisa/clientflow-ai`
- Supabase database credentials (Session pooler — same as local)
- OpenAI API key with billing enabled
- A [Vercel](https://vercel.com) account (free)
- A [Render](https://render.com) account (free)

**Order:** Deploy the **backend on Render first**, then the **frontend on Vercel** (so you have the API URL for `VITE_API_URL`).

---

## Step 1 — Deploy backend on Render

1. Go to [dashboard.render.com](https://dashboard.render.com) → **New +** → **Blueprint**
2. Connect your GitHub account and select the `clientflow-ai` repo
3. Render detects `render.yaml` — click **Apply**
4. Render asks you to fill in secret env vars. Add these:

| Variable | Value |
|----------|-------|
| `DATABASE_URL` | `jdbc:postgresql://aws-1-eu-central-1.pooler.supabase.com:5432/postgres?sslmode=require` (your pooler host) |
| `DATABASE_USERNAME` | `postgres.YOUR_PROJECT_REF` |
| `DATABASE_PASSWORD` | Your Supabase database password |
| `CORS_ORIGIN` | `http://localhost:5173` for now — update after Vercel deploy |
| `OPENAI_API_KEY` | Your OpenAI key |

`JWT_SECRET` is auto-generated by Render.

5. Wait for the deploy to finish (first build takes ~5–10 min)
6. Copy your live API URL, e.g. `https://clientflow-api.onrender.com`
7. Test: open `https://YOUR-API.onrender.com/api/health` — should show `"status":"ok"`

> **Free tier note:** Render sleeps after ~15 min of inactivity. The first request after sleep takes 30–60 seconds to wake up. Normal for portfolio projects.

---

## Step 2 — Deploy frontend on Vercel

1. Go to [vercel.com/new](https://vercel.com/new) → import `clientflow-ai` from GitHub
2. Configure the project:

| Setting | Value |
|---------|-------|
| **Framework Preset** | Vite |
| **Root Directory** | `frontend` |
| **Build Command** | `npm run build` |
| **Output Directory** | `dist` |

3. Add environment variable:

| Variable | Value |
|----------|-------|
| `VITE_API_URL` | `https://YOUR-API.onrender.com` (your Render URL, no trailing slash) |

4. Click **Deploy**
5. Copy your Vercel URL, e.g. `https://clientflow-ai.vercel.app`

---

## Step 3 — Connect frontend and backend (CORS)

Go back to **Render** → your `clientflow-api` service → **Environment**:

Update `CORS_ORIGIN` to include both local and production:

```
http://localhost:5173,https://YOUR-APP.vercel.app
```

No spaces after the comma. Save — Render redeploys automatically.

---

## Step 4 — Verify production

1. Open your Vercel URL
2. Register a new account (production has its own user data)
3. Add a client → add meeting notes → **Process with AI**
4. Check tasks on the Tasks page

If login fails with a network error, check:
- `VITE_API_URL` on Vercel points to the correct Render URL
- `CORS_ORIGIN` on Render includes your exact Vercel URL (with `https://`)

## Environment variables reference

### Backend (Render)

| Variable | Required | Description |
|----------|----------|-------------|
| `DATABASE_URL` | Yes | Supabase JDBC URL (Session pooler) |
| `DATABASE_USERNAME` | Yes | `postgres.PROJECT_REF` |
| `DATABASE_PASSWORD` | Yes | Supabase DB password |
| `JWT_SECRET` | Yes | Long random string (auto-generated on Render) |
| `CORS_ORIGIN` | Yes | Comma-separated frontend URLs |
| `OPENAI_API_KEY` | Yes | OpenAI API key |
| `OPENAI_MODEL` | No | Defaults to `gpt-4o-mini` |
| `PORT` | Auto | Set by Render — do not override |

### Frontend (Vercel)

| Variable | Required | Description |
|----------|----------|-------------|
| `VITE_API_URL` | Yes | Render backend URL, e.g. `https://clientflow-api.onrender.com` |

## Redeploying after code changes

Both platforms auto-deploy when you merge to `main` on GitHub:

- **Vercel** — rebuilds frontend on every push to `main`
- **Render** — rebuilds backend on every push to `main`

No manual redeploy needed after the initial setup.

## Troubleshooting

| Problem | Fix |
|---------|-----|
| API requests fail / CORS error | Check `CORS_ORIGIN` on Render matches your Vercel URL exactly |
| `openai: missing` on health check | Add `OPENAI_API_KEY` on Render and redeploy |
| First request very slow | Render free tier waking from sleep — wait ~60s and retry |
| Deploy fails: `max clients reached in session mode` | Supabase pool limit hit — stop local backend (`Ctrl+C`), wait 2 min, redeploy on Render |
| 502 on AI processing | OpenAI key invalid or no billing — check Render logs |
| Login works locally but not prod | `VITE_API_URL` missing or wrong on Vercel |

**Render logs:** Render dashboard → your service → **Logs**  
**Vercel logs:** Vercel dashboard → your project → **Deployments** → click latest → **Functions / Build Logs**

### Supabase connection limit (important)

Supabase Session pooler allows **15 connections** on the free tier. Spring Boot defaults to 10 connections per instance — so local dev + Render together can exceed that and crash the deploy.

This project limits the pool to **3 connections** in `application.yml`. If deploy still fails:

1. Stop your **local backend** (`Ctrl+C` in the backend terminal)
2. Wait **2 minutes** for Supabase to release connections
3. On Render → **Manual Deploy** → **Deploy latest commit**
